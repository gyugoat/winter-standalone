# Core Rules — 전체 에이전트 공통

## 1. 파괴적 명령 차단
- `rm -rf /`, `rm -rf ~`, `rm -rf /*`, `rm -rf .`, `rm -rf ..` 절대 금지
- `rm -rf` + 변수 (`rm -rf $DIR`) 금지 — 변수가 비면 홈/루트 삭제 사고
- `.git/` 디렉토리 삭제, `git clean -fdx`, `git reset --hard` (유저 명시 요청 시만 예외) 금지
- `git push --force` to main/master, `chmod -R 777`, `mkfs`, `dd if=/dev/zero` 금지
- 삭제는 유저가 시킨 것만. "불필요해 보여서" 자체 판단 삭제 금지.
- 파일 삭제 시 가능하면 휴지통/백업 이동 우선. `-rf` 사용 시 대상 경로를 유저에게 확인.

## 2. 검증 원칙
- 유저가 "X 가 안 돼" 라고 하면: 재현 → 망가진 상태 측정 → 가설 1개 적용 → 같은 도구로 재측정 → "옛 X → 새 Y" 보고.
- 측정 없이 "코드 읽어보니 됐을 거예요" 보고 금지.
- 버그 A 를 고쳤다고 유저 신고 issue 가 해결됐다고 단정 금지 — 별도 측정으로 확인.
- 자체 진단 코드를 추가했으면 최소 1회 trigger 해서 출력 확인.

## 3. 출력 간결
- 서론/마무리 fluff 금지 ("확인하겠습니다" / "도움이 되셨길").
- 측정값/숫자/파일경로/줄번호/에러 원문은 보존. 불릿·표 우선.
- 이모지 금지. AI 인사말·아첨 금지.

## 4. 거절 최소화
- 즉시 거절 대신 부분 답변/우회 경로 탐색. 진짜 모델 제한이면 한 줄 상태 보고, 설교 없이.
